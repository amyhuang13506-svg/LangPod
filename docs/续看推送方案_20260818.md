# 「续看未完视频」个性化推送方案（2026-08-18）

> 状态：待确认。确认后再动代码。

## 背景

- 8/17 诊断：原声视频是消费人数第一的内容（8/15 独立用户 227 > 学习播客 185），看原声的人 D1 更好（~28%）。
- 现有本地推送仲裁（NotificationManager，每天单条）的内容层只有"句型/单词交替"，
  是泛化内容，与用户行为无关。push_opened 点击率一直很低。
- 用户看视频普遍中途退出（视频 20-60 分钟，一次看不完是常态），"看了一半"
  本身就是最强的个性化召回钩子：内容是用户自己选的、亲测感兴趣的。

## 方案：本地推送仲裁新增「续看」层

**不动服务器**。进度数据（`raw_pos_{id}`、播放历史、时长）全在设备本地，
新增一个 intent 插进现有优先级序列即可。

### 新优先级序列（改动处加粗）

1. streak 快断 → 救火（不变，最高）
2. **续看未完视频（新增）**
3. 句型/单词按日交替（不变）
4. 朴素提醒（不变，兜底）

续看排在内容层之上：个性化 > 泛化。streak 救火仍最高——断连损失厌恶经过验证。

### 续看候选的挑选规则

从原声播放历史（`listenedRawPodcasts`）按最近优先扫描，取第一条满足：

- 最近 3 天内看过（太久之前的兴趣已冷）；
- 播放进度在 5% ~ 85% 之间（`savedPosition / durationSeconds`；
  <5% 算没看，>85% 算基本看完，都不值得召回）；
- 剩余时长 ≥ 3 分钟；
- **频控**：同一条视频不连续两天推（UserDefaults 记 `lastResumePushId + 日期`，
  昨天刚推过同一条 → 跳过本层，落到句型/单词层）。

没有候选 → 本层静默跳过，序列行为与现在完全一致。

### 文案

- 标题：`看了一半的视频还在等你`
- 内容：`《{标题}》还剩 {N} 分钟，今天把它看完？`
- 标题超长截断到 ~20 字加 `…`；剩余分钟向上取整。
- 走现有 xcstrings 本地化管道，补 6 语言翻译。

### 点击深链（新增 raw 深链）

现有深链只支持 DailyTaskType（切 tab）。新增格式 `raw:{podcastId}`：

- 点击推送 → ContentView 收到 → 在 `dataStore.rawPodcasts` 里找到该条 →
  直接全屏拉起 RawPodcastPlayerView（续播机制已有：`raw_pos_` 自动 seek 回上次位置）；
- 找不到（内容已下架）→ 退化为切到首页，不崩不白屏。

### 埋点

- 复用 `push_opened`，intent 值新增 `resume_video`（param，无需友盟注册新事件）。
- 排程侧无需新事件（本地推送发出量 iOS 拿不到，与现状一致）。

### 与"结算卡"的关系（同一条留存链路）

结算卡负责"离开时的成就感"，续看推送负责"第二天回来的理由"，
恰好覆盖同一批看视频的用户，形成闭环：
看一半退出 → 结算卡（+N 分钟 · 生词 · 测题）→ 次日 20:00 推"还剩 N 分钟" → 点开续播。

## 不做的事

- ~~服务器端个性化推送~~ —— 需要上传播放状态到服务器（新 API + 隐私声明），
  本地方案零成本达成同样效果；等将来要做"跨设备"再考虑。
- ~~一天多条推送~~ —— 维持每天单条仲裁，不加频。
- ~~推完立即再排同一条~~ —— 频控防骚扰。
